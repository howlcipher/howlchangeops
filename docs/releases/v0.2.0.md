# HowlChangeOps v0.2.0 (unreleased)

## Machine-readable results
`version`, `evaluate`, `approve`, `execute`, `rollback`, `history` and
`explain` accept `--json` and print one `howl.result/v1` envelope on stdout
(see README, "Machine-readable output"). Callers such as HowlPlane no longer
need to parse `Decision:` / `Decision saved as` lines or guess the newest
decision file. `howlchangeops interop --json` prints the `howl.interop/v1`
descriptor `howl doctor` uses to check that callers still match.

Text output and exit codes are unchanged.

## Configuration location
The repository configuration is read from `HOWLCHANGEOPS_CONFIG`, then
`$XDG_CONFIG_HOME/howlchangeops/howlchangeops-config.json`, then the legacy
working-directory paths. A configuration kept in the XDG directory survives
`howl update`, which replaces the release directory.

## HowlFrame compatibility
Any HowlFrame 0.1.x patch release is accepted when its `--version` reports
`HFBC format: 1`, instead of exactly 0.1.0. A different minor release or
bytecode format is still refused with `HOWLFRAME_INCOMPATIBLE`.

## Approval is the owner's decision
`approve` asks for confirmation at a terminal and, without one, refuses with
`OWNER_CONFIRMATION_REQUIRED` unless `--owner-confirmed` relays a decision the
owner gave. Approvals record the real approver (`--approver` or the OS user,
never a fixed `admin`) and the confirmation mode, both signed. Approvals signed
by 0.2.0 development builds before this change no longer verify; they expire
after 30 minutes anyway. (Issue #13.)
