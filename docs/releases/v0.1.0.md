# HowlChangeOps v0.1.0

## What it is
HowlChangeOps is a policy-driven release controller and authority execution
boundary for the Howl ecosystem, built on HowlFrame. It inspects a proposed
change, evaluates it against a compiled HowlFrame policy, requires human
HMAC approval for anything the policy doesn't auto-allow, and only then
executes the bounded action -- recording an evidence-backed receipt and
supporting governed rollback.

## Compatibility
This release's compiled policy (`howlchangeops.hfbc`) was built and verified
against **HowlFrame v0.1.0**. `howlchangeops --version` reports both its own
version and the HowlFrame version its policy artifact was compiled against.

## Release artifact
Each platform archive contains:
- `howlchangeops` (or `howlchangeops.exe` on Windows) -- the adapter binary
- `changeops` -- an identical copy, for the documented compatibility alias
- `howlchangeops.hfbc` -- the compiled policy, evaluated by the HowlFrame VM
- `howlchangeops-config.example.json` -- a starting point for
  `config/howlchangeops-config.json`

## Verification
`howlchangeops --version` succeeds with no configuration present -- this is
what Howl's installer uses as the post-install health check. Every other
command (`inspect`, `validate`, `plan`, `evaluate`, `approve`, `execute`,
`rollback`, `explain`) requires a real `config/howlchangeops-config.json`
pointing at the repositories to govern.
